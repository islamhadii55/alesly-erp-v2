# API الطابعات المتعددة

تتم تهيئة جداول SQLite تلقائيًا عند تشغيل `app.py` عبر `printer_support.py`.
جميع المسارات تتطلب جلسة دخول، ومسارات الإدارة تتطلب دور `مدير`.

## الملفات

- `printer_support.py`: المخطط، الترحيل التلقائي، ومسارات API.
- `printer_adapters.py`: محول ESC/POS للطابعات الحرارية عبر TCP/IP.
- `app.py`: تسجيل الوحدة وتهيئتها عند بدء التطبيق.
- `templates/printers.html`: واجهة إدارة الطابعات والربط وطابور المهام.

## واجهة المستخدم

للمدير: `/printers`، وتوفر إنشاء ملفات الطابعات، إضافة طابعات الشبكة أو USB أو Windows،
تعيين الافتراضية، اختبار اتصال TCP، ربط أنواع المهام، ومراجعة آخر مهام الطباعة.

## أنواع الطابعات

- `thermal`: إيصالات، التنسيق المعتاد `esc_pos`.
- `barcode`: ملصقات باركود، التنسيقات `zpl` أو `tspl`.
- `invoice`: فواتير وتقارير، التنسيق المعتاد `pdf`.

## المسارات

| الطريقة | المسار | الصلاحية | الوصف |
|---|---|---|---|
| `GET` | `/api/printer-profiles` | دخول | عرض ملفات الطابعات |
| `POST` | `/api/printer-profiles` | مدير | إنشاء ملف طابعة |
| `GET` | `/api/printers` | دخول | عرض الطابعات |
| `POST` | `/api/printers` | مدير | إنشاء طابعة |
| `GET/PATCH/DELETE` | `/api/printers/:id` | دخول/مدير | عرض أو تعديل أو تعطيل طابعة |
| `POST` | `/api/printers/:id/default` | مدير | تعيين الافتراضية |
| `POST` | `/api/printer-assignments` | مدير | ربط نوع مهمة بطابعة |
| `GET` | `/api/printer-assignments` | دخول | عرض الربط |
| `POST` | `/api/print-jobs` | دخول | إضافة مهمة إلى الطابور |
| `GET` | `/api/print-jobs/:id` | دخول | متابعة مهمة |
| `POST` | `/api/print-jobs/:id/cancel` | دخول | إلغاء مهمة queued |
| `POST` | `/api/printers/:id/health` | دخول | تسجيل فحص اتصال |
| `GET` | `/api/print-errors` | دخول | تقرير المهام الفاشلة وانقطاعات الاتصال |

## مثال إنشاء مهمة

```json
{
  "job_type": "invoice",
  "payload_format": "pdf",
  "payload": {"invoice_id": 123},
  "copies": 1,
  "branch_id": 1,
  "workstation_id": "POS-01"
}
```

يمكن إرسال `Idempotency-Key` في رأس الطلب لمنع إنشاء المهمة نفسها مرتين.
يتم اختيار الطابعة الصريحة أولًا، ثم الأكثر تخصصًا حسب محطة العمل والفرع، ثم الافتراضية.

## طباعة الباركود التلقائية

عند إنشاء منتج جديد من `/products`، يتم إنشاء مهمة `barcode_label` تلقائيًا إذا كان خيار
`auto_barcode_print` مفعّلًا (مفعّل افتراضيًا) ووجدت طابعة نشطة من نوع حراري أو باركود.
تستخدم المهمة باركود المنتج أو SKU، وتُحفظ في `print_jobs` دون إرسال مباشر للطابعة.

## محول الطابعة الحرارية

`ThermalTCPAdapter` يتصل بعنوان `address` والمنفذ `port` (الافتراضي 9100)، ويدعم:

- `test_connection`: فحص قابلية الوصول.
- `print_bytes`: إرسال bytes خام.
- `print_receipt`: إيصالات ESC/POS.
- `print_barcode_label`: ملصق Code128 عبر ESC/POS.

لا يتم فتح اتصال أو إرسال بيانات إلا عند استدعاء إحدى هذه العمليات صراحة.

## تشغيل عامل الطباعة

العامل الفعلي موجود في `printer_worker.py` ويُشغّل عبر:

```bash
python printer_worker.py --poll-seconds 1 --max-attempts 3 --retry-delay 2
```

يوجد أمر `worker` مستقل في `Procfile` حتى يعمل بجانب خدمة الويب دون إنشاء أكثر من عامل
يتنافس على المهمة نفسها. يقوم العامل بحجز المهمة ذريًا، ويرسل ملصقات ESC/POS عبر TCP/IP،
ثم يسجل النجاح أو يعيد المحاولة. بعد فشل الحد الأقصى من المحاولات تصبح المهمة `failed`
وتتحول الطابعة إلى حالة `error` مع حفظ رسالة الخطأ.

## تقرير الأعطال

- واجهة `/printers` تعرض تقرير المهام الفاشلة وانقطاعات الاتصال.
- API: `GET /api/print-errors` يعيد `failed_jobs` و`connection_failures` حتى 100 سجل.
- كل فشل اتصال يسجل في `printer_health_checks`، مع عنوان الطابعة والمنفذ ورسالة النظام.
- بعد نجاح إرسال مهمة، تُعاد الطابعة إلى `active` ويسجل العامل فحص وصول ناجح.

> فحص الاتصال الفعلي عبر TCP أو USB أو Windows Spooler يحتاج Adapter خاص ببيئة التشغيل. المسار الحالي يسجل عدم توفر الـ Adapter بدل الإدعاء بنجاح اتصال غير منفذ.
